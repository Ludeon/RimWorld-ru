# DefInjected и дефы

Открывай этот файл, когда вопрос касается `**/DefInjected/**/*.xml`: к какому дефу и полю относится строка, почему инъекция не применяется, как устроены дефы в `.Data/<DLC>/Defs/`.

## Дефы (`.Data/<DLC>/Defs/**/*.xml`, только чтение)

Дефы — это игровая база данных в XML: описания сущностей, состояний, событий и т.д.

- Корневой элемент — `<Defs>`, в нём плоский список дефов.
- Тег элемента — **тип дефа** (`ThingDef`, `HediffDef`, ...). Это имя C#-класса в `.Decompiled/`, а дочерние элементы дефа — поля этого класса.
- Уникальное имя дефа задаётся в дочернем элементе `<defName>`.
- Наследование: атрибут `ParentName="X"` ссылается на деф с атрибутом `Name="X"`. Такой родитель обычно помечен `Abstract="True"` и в игре сам не существует.
- Имена папок и файлов в `Defs/` ни на что не влияют.

## Формат файла инъекций

Корневой элемент `LanguageData`, в нём плоский список элементов:

- **имя тега** — путь к полю дефа;
- **значение** — перевод: обычная строка или, для списковых полей, набор `<li>`.

Над каждым элементом стоит комментарий с английским оригиналом.

## Путь инъекции

Игра находит поле так:

1. **Имя папки**, в которой лежит файл (`DefInjected/<ТипДефа>/`), — это тип дефа. Регистр должен совпадать точно. Имя самого файла не важно.
2. Путь из тега делится по точкам `.`. **Первая часть** — `defName` дефа.
3. Каждая следующая часть обрабатывается по первому подходящему правилу:
   1. **Число** → элемент списка с этим номером (счёт с 0): `stages.0`.
   2. **Имя поля** текущего объекта → переход в это поле: `label`, `comps`.
   3. **Текущий объект — список, часть не число и не поле** → элемент списка **по имени** (handle). Имя — это значение поля, помеченного в коде атрибутом `[TranslationHandle]`: например, класс компонента (`compClass`) у `comps` или `def` у частей тела.
      Пример: `comps.HediffComp_MessageAboveSeverity`.
   4. **`имя-N`** → N-й (счёт с 0) из элементов списка с одинаковым именем.
4. Последний найденный объект — это поле, которое будет заменено.

Логика реализована в `Verse.DefInjectionPackage.SetDefFieldAtPath` и `Verse.TranslationHandleUtility`. Если этот текст расходится с кодом, прав код.

**Пример.** `Anomaly/DefInjected/HediffDef/Hediffs_Global_Misc.xml`:

```xml
<DuplicateSickness.comps.HediffComp_MessageAboveSeverity.message>...</DuplicateSickness.comps.HediffComp_MessageAboveSeverity.message>
```

Тип `HediffDef` → деф с `defName` `DuplicateSickness` → поле `comps` → элемент списка, у
которого `compClass` = `HediffComp_MessageAboveSeverity` → поле `message`.

## TKeys

Прежде чем разбирать путь, игра проверяет, не является ли он **TKey** — коротким псевдонимом длинного пути. Если является, она подставляет полный путь и разбирает уже его.

TKey берётся из двух источников:

- **атрибут `TKey` в дефе.** В `.Data/Core/Defs/Misc/TipSetDefs/Tips.xml` есть `<li TKey="DismissLetters">` в списке `tips` дефа `GameplayTips`, поэтому перевод записывается как `<GameplayTips.DismissLetters>`;
- **хардкод** в `Verse.TKeySystemHardcodedMapping`. Например, `BuildMonumentWorker.LetterLabelMonumentRuined` → `BuildMonumentWorker.root.nodes.12.elseNode...label`.

Логика реализована в `Verse.TKeySystem`.
