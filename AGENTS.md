# RimWorld-ru — инструкции для ИИ-агентов

**Обязательно перед ответом:** вопрос про плейсхолдер `{0}`/`{ИМЯ}`/`{ИМЯ_Подсимвол}` →
сначала открой `docs/agents/howto-resolve-placeholder.md`. Никогда не указывай путь к файлу,
класс/метод или номер строки, если не получил его только что из реального результата
grep/read в этом же ответе.

Это официальный репозиторий русской локализации игры RimWorld (`Ludeon/RimWorld-ru`).
Переводчики — не программисты; твоя задача — помогать им разбираться в механике локализации и в коде игры, а не писать код самой игры.

## Общие принципы

- Не угадывай и не выдумывай. Если что-то не нашёл — честно скажи об этом. Если не знаешь, как искать — спроси напрямую.
- Если у тебя есть инструменты для поиска, анализа и модификации — используй их вместо того, чтобы писать переводчику пошаговую инструкцию, которую он должен выполнить руками; если инструментов нет — скажи прямо, не имитируй их наличие.
- Отвечай по существу, без воды; объёмные разборы — только когда они действительно нужны.

## Структура репозитория

Локализация разбита по DLC: `Core/` (основная игра), `Royalty/`, `Ideology/`,
`Biotech/`, `Anomaly/`, `Odyssey/`. Файлы в этих папках (и вложенных) — то, что
можно и нужно менять. Внутри каждой:

- `Keyed/*.xml` — плоские наборы "ключ → строка" (UI-тексты, письма, диалоги);
- `DefInjected/<ТипДефа>/*.xml` — переопределение строковых/списковых полей дефов;
- `Strings/` (не везде) — таблицы/списки слов для генерации текста;
- `WordInfo/` (не везде) — падежный словарь (`Case.txt`), таблицы рода, множественного числа и т.д.

Подробности механики — в `docs/agents/`. Выбери файл по вопросу:

| Вопрос | Файл |
|---|---|
| Что подставится в `{0}` / `{ИМЯ}` / `{ИМЯ_Подсимвол}` в конкретной строке? | [`howto-resolve-placeholder.md`](docs/agents/howto-resolve-placeholder.md) |
| Как разобрать или записать `{...}`: `_`, `?`, `lookup`, `replace`, `{{ }}`, вложенность, ошибки | [`placeholder-syntax.md`](docs/agents/placeholder-syntax.md) |
| Формат `Keyed/*.xml`, где в коде используется ключ | [`keyed-strings.md`](docs/agents/keyed-strings.md) |
| Формат `DefInjected/**`, путь инъекции, TKeys, устройство дефов | [`def-injected.md`](docs/agents/def-injected.md) |

Если вопрос переводчика подпадает под тему одного из файлов выше — **первым действием
открой этот файл инструментом чтения**, даже если кажется, что уже помнишь его содержание,
и следуй тому, что там написано. Самостоятельный поиск по `.Decompiled`/`.Data` — это шаг,
который сами документы предписывают как часть алгоритма (например, шаг 1 в
`howto-resolve-placeholder.md`), а не альтернатива чтению документа. Переходи к независимому
поиску, только если ни один документ вопрос не покрывает, — и в этом случае прямо скажи, что
готового документа не нашлось.

## Локальные вспомогательные папки (только для чтения)

Помимо переводов, в воркспейсе (не в git — заводятся через `script/setup.ps1`,
требуют локально установленной через Steam копии RimWorld) есть:

- `.Decompiled/**` — декомпилированный (ILSpy) исходный код игры на C#;
- `.Data/<DLC>/{Defs,Keyed,Strings}/**` — оригинальные англоязычные данные игры.

Файлы в этих двух папках **нельзя менять** и предлагать в них правки — используй их только для анализа: какие данные подставляются в плейсхолдеры, в каких игровых ситуациях вызывается строка, какая сущность связана с переводимым текстом. Если `.Decompiled`/`.Data` отсутствуют (юнкшены не настроены) — скажи об этом прямо и посоветуй запустить `script/setup.ps1`.

## Инструменты

- `python tools/parse_placeholder.py "{текст}"` — механически разбирает конструкцию `{...}` на Символ, Подсимвол, Функцию и Аргументы (в том числе вложенные). `--json` — вывод в JSON.
- `python tools/subsymbols.py <ТипC#>` — список Подсимволов, доступных для C#-типа, прямо из `.Decompiled/Verse/GrammarResolverSimple.cs`. Без аргумента — список всех известных типов.

## CI-проверки

Перед тем как предлагать финальный текст перевода, помни про автоматические проверки в `.github/workflows/` (прогнать локально: `script/test.ps1`): кодировка UTF-8 с BOM, оформление тире, отсутствие точки в конце `reportString`, валидность XML, согласованность рода в `WorldInfo`.
