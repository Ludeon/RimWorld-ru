# DefInjected

DefInjected ("инъекции") - это файлы в формате xml, в которых содержатся данные, предназначенные для переопределения значений из дефов (Defs) игры. В проекте локализации этот формат служит для замены значений строковых и списковых полей дефов на русскоязычные.

## Структура

Файл инъекций состоит из корневого XML-элемента `LanguageData`, которому подчинена плоская (за исключением списковых значений) структура XML-элементов инъекций. 

Имя тега элемента инъекции представляет путь полю дефа, значение которого следует подменить.

Значение элемента - это то, **на что** заменяется значение поля дефа. Значения бывают двух типов:

- строковый - простая строка для замены строки в дефах
- списковый - представляет собой набор элементов `<li>` со строковыми значениями. Предназначен для замены списковых полей в дефах

Над каждым элементом инъекции находится xml-комментарий, в котором указывается оригинальный текст заменяемого дефа

## Путь инъекции

Для поиска места, где будет применена инъекция, игра использует следующие данные:

- **Имя подпапки**, где непосредственно находится файл инъекции, указывает на *имя типа дефа*, подлежащего модификации. Соответствие имени папки и имени типа дефа должно быть полное, включая регистр.
- **Имя тега элемента инъекции** определяет *путь к полю* дефа, подлежащему модификации

Имя самого xml-файла не имеет значения для пути инъекции.

*Путь к полю* состоит из одного или нескольких фрагментов, разделённых точкой `.`. Чтобы найти конечную *цель инъекции*, игра их парсит по-порядку особым образом:

Первый фрагмент пути всегда является названием дефа, подлежащего модификации. Игра назначает xml-элемент этого дефа *текущим элементом* поиска и продолжает чтение пути.

Остальные фрагменты пути игра читает по-разному, в зависимости от формата и *текущего элемента*, найденного по уже прочитанным фрагментам пути:

- ***Текущий элемент* является коллекцией.** В этом случае по *текущему фрагменту пути* игра пытается вычислить индекс в коллекции. Затем будет искать в *текущем элементе* дочерний элемент списка (`<li>`), по найденному индексу (нумерация с 0). Найденный по индексу элемент назначается новым *текущим элементом*, и чтение продолжается.
- ***Текущий фрагмент пути* - имя дочернего элемента в *текущем элементе* дефа.** В этом случае этот дочерний элемент назначается текущим, и чтение продолжается.

Последний найденный *текущий элемент* и является *целью инъекции*

Механизм парсинга описан в классе `Verse.DefInjectionPackage` кода игры в методе `SetDefFieldAtPath`. При противоречии этой инструкции с кодом следует руководствоваться кодом.

### Пример

Допустим, в файле `Core/DefInjected/ConceptDef/Concepts_NotedSelfshow.xml` находится строка:

```xml
<Stockpiles.label>Склады</Stockpiles.label>
```

Чтобы осуществить инъекцию, игра будет искать деф с типом `ConceptDef` и названием `Stockpiles`. Он есть в файле `.Data\Core\Defs\Tutor\Concepts_NotedSelfshow.xml` и представляет собой такую структуру:

```xml
  <ConceptDef>
    <defName>Stockpiles</defName>
    <label>Stockpiles</label>
    <priority>40</priority>
    <helpText>Your colonists need somewhere to store items. Designate a STOCKPILE for them to store things.\n\nFind the stockpile in the ZONES section of the ARCHITECT menu in the lower-left.</helpText>
    <highlightTags>
      <li>MainTab-Architect-Closed</li>
      <li>DesignationCategoryButton-Zone-Closed</li>
      <li>Designator-ZoneAddStockpile_Resources</li>
    </highlightTags>
  </ConceptDef>
```

И игра в этом дефе в поле `label` заменит значение `Stockpiles` на локализованное значение `Склады` из инъекции.

## TKeys

*Путь к полю* может являться ключом в особом *словаре TKeys*, который игра хранит в памяти. Этот механизм позволяет упростить, сократить и сделать читаемыми пути, которые без механизма TKeys были бы слишком длинными и сложными.

Игра первым делом ищет *путь к полю* в *словаре TKeys*, и только потом переходит к стандартному описанному выше поиску цели инъекции.

Словарь TKeys заполняется из следующих источников:

- **Дефы.** У дочернего элемента дефа может быть задан атрибут `TKey`. Его значение и будет ключом в *словаре TKeys* для пути этого поля дефа.
- **Хардкод**. Некоторые птуи прописаны напрямую в классе `Verse.TKeySystemHardcodedMapping` в коде игры.

Пример:
В файле инъекции задан *путь к полю* `BuildMonumentWorker.LetterLabelMonumentRuined`. Этот ключ зарегистрирован в словаре TKeys хардкодом. Ему соответствует путь `BuildMonumentWorker.root.nodes.12.elseNode.elseNode.nodes.1.elseNode.elseNode.node.nodes.1.node.nodes.0.label`.

Если игра находит *путь к полю* в словаре TKeys, она заменяет его на значение по этому ключу, и продолжает поиск по уже новому *пути к полю*.

Механизм описан в классе `Verse.TKeySystem` кода игры. При противоречии этой инструкции с кодом следует руководствоваться кодом.
